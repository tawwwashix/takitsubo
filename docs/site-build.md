# ビルドの保守

生成HTMLは引き続きGitに保存する。手元とGitHub Actionsは、同じJSONと生成処理から同じページを作る。公開方式・RSS取得・AWQ同期の手順は変更していない。

## コマンド

```text
python scripts/build.py
python scripts/build.py --page lab
python scripts/build.py --page shindan
python scripts/build.py --page lab --page shindan
```

全体ビルドは毎週のデータ更新にも使う。`--page` は既存の生成済みJSONを使ったページのみの再生成で、データ更新や共通CSS/JS変更時の全体ビルドの代用にはしない。

`update_from_rss.py` / `sync_awq.py` / `fetch_images.py` からの呼び出し先は従来の `scripts/build.py` のまま。`title_audit.py` が読み込む `games_db()` も入口に残している。新しい依存パッケージは不要。

## 編集する場所

| ファイル（`scripts/sitebuild/` 内） | 担当 |
| --- | --- |
| `cli.py` | 引数と生成順序。検索・診断JSONをHTMLより先に生成 |
| `context.py` | リポジトリルートと既存JSONの読み込み |
| `common.py` | ヘッダー・フッター・カード・書式・アセットバージョン |
| `catalog.py` | エピソード内のゲーム情報、名寄せ、読み、診断用データ、DB集計 |
| `home.py` | トップページ・おすすめ回 |
| `episodes.py` | エピソード一覧・個別ページ・検索JSON |
| `series.py` | 名物企画一覧・個別ページ |
| `awq.py` | アートワーククイズ・ランキング |
| `games.py` | 滝壺データベースのHTML |
| `shindan.py` | 診断ページ・診断JSON |
| `pages.py` | 研究所、お知らせ、聴き方、おたより、プライバシー |
| `sitemap.py` | サイトマップ・robots.txt・更新日の検証 |
| `output.py` | 内容が変わったファイルだけ書き込む共通処理 |

HTMLの組み立て方と表示内容は従来のまま移動した。テンプレートエンジン導入などは行っていない。生成HTMLを直接編集せず、上記の生成元を編集してビルドする。

## 聴き方・おたより・プライバシーの更新日

`data/page_meta.json` の該当ページの `updated` を、**本文を実質的に変更した日**に更新する。

```json
"guide.html": {"updated": "2026-10-25"}
```

日付は `YYYY-MM-DD`。全体をビルドすると `sitemap.xml` のそのページの `lastmod` に反映される。単なる再ビルド・共通フッターや装飾の変更だけでは更新しない。日付不明なら `null` にすると `lastmod` を省略する。不正な日付や必要なページの欠落は、出力前にエラーにする。

初期値の `2026-07-11` は、3ページの現在の本文につながる最後の変更をGit履歴（`0943c742`）で確認して設定した。ファイルの保存時刻や今回のビルド日ではない。他のページの更新日規則（配信日・掲載日など）は今回維持している。

## 不要な差分を減らす仕組み

- 同じ内容の出力は書き直さず、ファイルの更新時刻も保つ。
- DBの個別ページは毎回削除せず、生成対象から外れた `games/g*.html` だけを削除する。生成ページの名前空間なので、手書きページをこの名前で置かない。
- 診断本体は `assets/js/shindan/main.js`。診断のHTMLに専用の内容ハッシュを付け、そのページでだけ読み込む。`assets/js/shindan.js` は共通の小さなローダーとして残す。
- 研究所本体は `assets/js/lab/`。子モジュールを含む内容ハッシュを研究所のHTMLにだけ付ける。
- 共通CSS・共通JS・メニューなどの変更では、全ページに差分が出る場合がある。音声を保ったページ移動時の整合性も担う共通バージョンなので、必要な差分まで隠さない。

今回、診断ローダーへの切り替えでは全ページの参照が一度更新される。以後の**診断本体だけの変更**では診断HTMLだけ、**研究所JSだけの変更**では研究所HTMLだけが変わる。コード分割自体ではHTML・データの内容を変えない。

## 検証

```text
python scripts/test_site_build.py
python scripts/test_site_build.py --reference-ref b2f14a65
python scripts/test_lab_build.py
python scripts/audit_lab_generated.py
node scripts/test_lab_suite.cjs --site
```

`test_site_build.py` は `.local-preview/` 内の一時コピーで動き、RSSへの通信・本物のデータ更新・Git操作はしない。全体の再生成、同内容の保存時刻維持、不要なDBページの除去、診断・研究所だけの変更、静的ページ更新日の検証、新しい回が増えた場合、既存ツールからのimportを確認する。`--reference-ref` は分割直前の単一ファイル版と出力をバイト単位で比較するための任意オプション（指定コミットをローカルで参照できる場合）。

ブラウザ検証はプレビューを起動し、既存のPlaywrightを `NODE_PATH` で指定して行う。診断モジュールの版の切り替え・取得失敗、音声を保持したページ移動も含む。生成物監査は研究所着手前の `6471908e` を固定基準として比較する。main統合後も比較基準は変わらない。必要な場合は `--base-ref` で明示指定できる。許容するデータ変更は `page_meta.json` と2026-10-27付の研究所のお知らせ追加のみで、既存のお知らせやエピソード・DB・ランキングデータの変更は検出する。

このテストはGitHub Actions上の実行や実際のRSS取得を代替しない。週次処理と公開設定を変更せず、その後段のビルドを同じ入口で検証する。

### 2026-10-25 の確認結果

- 分割前（`b2f14a65`）との731ファイル比較はバイト単位で一致。新しい回を一時コピーに追加した場合も一致。
- 入力に変更がない全体ビルドでは、全出力の内容・保存時刻を維持。
- 診断本体だけの編集は `shindan.html` のみ、研究所の子JSだけの編集は `lab.html` のみ変更。
- 更新日の明示指定・日付不明時の省略・実行日に依存しないこと・不正日付で出力前に停止することを確認。
- ブラウザ検証18種類すべて成功。13種類のページを5段階の幅で確認し、音声の継続、保存・コピー、計測、診断本体の版の切り替えを検証。画面キャプチャも確認。
- mainとの既存715ページ比較は、許容した共通ナビ・ローダー・バージョン以外の本文変更なし。既存JSONの内容変更なし。
- 作業ツリーの全体ビルド後も、分割によるHTML・XML・データの追加差分なし。Python 3.12構文の解析も成功（実行環境はWindowsのPython 3.14）。
