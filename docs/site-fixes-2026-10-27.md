# AWQの先行登録と画像コピーの修正

## AWQの先行登録

AWQ第129回が同期済みで、エピソード一覧が第128回までの状態を、追加した入力検証が不正と判定していた。出題と答えのエピソードは同時に登録されるとは限らないため、出題回の検証を「正の整数・重複なし」に変更した。画像パスなどの検証は継続する。

出題が先行した場合は既存の「答えのエピソード情報は準備中です。」を表示し、エピソード登録後のビルドでリンクが現れる。架空のエピソードは作らない。

`test_site_validation.py` で、AWQ先行時の入力検証→全体ビルド→生成物検証と、その後にエピソードを追加した場合のリンク表示を一時コピーで確認した。不正入力は21ケースを確認し、すべて出力の変更前に停止した。実データの第129回の出題・画像を残した状態でもビルドと監査が成功した。

## 研究所・ゲーム診断の画像コピー

報告されたFirefoxの `http://192.168.11.2:8765/` は安全なコンテキストではなく、`navigator.clipboard` と `ClipboardItem` が提供されない。これは共通化前の診断でも必要だったブラウザの条件で、サイト内の処理だけでは解除できない。同じPCでは `http://localhost:8765/`、別端末ではHTTPSまたは画像保存を利用する。

共通化前はコピー成功時にボタンが「✅ コピーしました！」へ変わっていた。共通化後は別のステータス文へ変わっていたため、両ページで元のボタン表示と1.8秒後の復帰を戻した。画像生成と画面遷移時の破棄処理は共用を継続し、表示済みPNGのBlobをクリック直後にコピーする。コピー時に画像を再生成したり、非同期画像処理の完了を待ってからClipboard APIを呼んだりしない。

案内は画像と操作ボタンの間へ移動した。HTTPによる制限、API未対応、コピー拒否を区別し、成功を装う表示はしない。画像・選択の破棄時は保持したBlobとボタン復帰タイマーも破棄する。

## 確認結果

- Firefox 158.0.1の専用テストプロファイルで、localhost上の研究所・ゲーム診断を実クリックしてPNGコピー成功とボタン表示を確認。同じFirefoxで報告されたLAN内HTTPのAPI不在も確認した。既存のFirefoxプロファイル・設定は変更していない。
- Chromeではコピー許可を事前付与せずに両ページから実コピーし、後からクリップボードを読み取って表示画像との画素一致を確認。成功表示の復帰、再生成しないこと、拒否時の案内、実際の安全でないHTTPコンテキスト、320/390/1280pxでの案内位置も確認した。
- 共有・研究所のブラウザテスト16種類は、既存説明文の期待値更新後の個別再実行を含めて成功。最初の実行は15/16で、1本はコミット `8b16a009` の説明文変更に対して古い文言を期待していた。表示文言は変更せずテストを現在の文言に合わせた。
- ビルド回帰8項目・アセット回帰4項目が成功。実データの生成物監査は720ページ・44,479件のローカル参照・719件のサイトマップURLを確認した。
- 研究所・診断の生成HTMLは共有モジュールの参照バージョンだけが変更された。元から未コミットだったAWQ入力・画像、およびその再生成で変わったトップ・AWQページは修正コミットの対象から外した。

GitHub Actions上の実行、公開環境と実機iOS/Androidでのコピーは未検証。ログ・画面キャプチャ・専用テストプロファイルは `.local-preview/` にある。
