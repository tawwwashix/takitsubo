# エピソード研究所

博士が提示する3択から1回を選び、同じ3択を共有する、独立した研究所の試作。

## 起動

Worktree直下の `start-episode-lab.bat` をダブルクリック。
`scripts/preview_episode_lab.py` が `http://127.0.0.1:8766/lab.html` を開く。
このバッチは公開・ビルド・RSS更新・Git操作をしない。
同じWorktreeの専用サーバーが起動済みなら再利用し、別のプロセスがポートを使っている場合は上書きせず停止する。
旧プレビューを起動したまま更新した場合は、そのウィンドウを閉じてから新しいバッチを起動する。
ポートは以前と同じ8766なので、ブラウザの既存記録を引き継げる。

## 遊びと見た目

- `data/search.json` を再利用。第0回を除くエピソードから重複なしの3件を選ぶ。
- 最初は未選択。3枚のケースを横並びにし、タップ／クリックで1枚を大きくする。残りの2枚も押せる。
- 未選択と選択時のCSSグリッドは同じ3トラック構文を使い、初回から列幅を補間する。「別の3択」後も同様。OSの動きを減らす設定では補間しない。
- 見出し直下にランダムな3択と自由な収集を説明。取得ボタンは白文字の朱色で強調する。
- 候補の上では左右キーで切り替えられる。フォーカスやマウスオーバーだけでは選択しない。下の詳細欄でタイトル全文・回番号・日付・タグを読める。
- 大きな「手持ちに加える」は取得、小さな「エピソードを開く」は移動。取得せずに開くこともでき、開くだけでは図鑑に登録しない。取得後も研究所に留まる。
- セットの中間状態・挿入演出・残り2本を倒す演出・色付き台座は撤去。候補は3本とも浮遊し続け、調べている1本が大きくなって影と一緒に下（手前）へ来る。床は消失点に収束する線と奥ほど狭い横線で遠近感を示す。
- 博士は既存の `assets/img/hyuuma.webp` を使用。研究所内のCSSで左右反転し、右を向く。元画像と他ページの表示は変更しない。タイトルは下の詳細欄へ集約する。
- UI・共有画像・共有文・読み上げのエピソード番号は `#31` 形式。元のアートワークに描かれた文字やエピソードタイトルそのものは変更しない。
- 詳細欄は3候補の最大サイズをCSSグリッドで確保し、未選択時も同じ高さ。画面幅やフォント読み込みには追従する。タグがない場合の代替文は表示しない。
- 「別の3択」で即座に未選択の新しい組へ。候補が十分ある場合は直前の3件を除外する。未登録優遇はせず、候補内で等確率。
- エピソードへの移動や選択で再生を自動開始・切り替えしない。聴取状態も記録しない。
- ケースはオリジナルの段差・横溝・銘板を持ち、銘板は GAME NO TAKITSUBO。SVGで正面の凹凸を描き、側面はCSSの立体面で構成する。
- ケース色はエピソード番号のみから決定する32bitハッシュのv1規則。70%グレー、20%黒、10%その他6色を割り当てる確率設計であり、有限のエピソード数で厳密な比率にはならない。番号が同じなら端末・抽選順・図鑑・共有リンクに依存せず同色になる。既存色の維持のため、ハッシュ定数とパレット順序を不用意に変更しない。
- 図鑑にも同じ生成関数でケースを表示。図鑑の一覧は静止し、PCのホバー／フォーカスで1枚だけ軽く傾ける。側面の立体面は生成しない。

## 後で決めること

一日一回の制限、その初回ボーナス、取得ルールは最後にユーザーと改めて相談する。現段階では回数・日付による制限やカウンターを実装しない。デバッグ中は何度でも選び直せる。

## 保存

### 手持ち6本と図鑑

- 「手持ちに加える」で空きがあれば図鑑と手持ちに登録する。登録済みの手持ちは重複追加できない。図鑑の詳細から手持ちに戻すこともできる。
- 最大6本。満杯なら1つのウィンドウで「図鑑に登録する」（既存なら「図鑑に残す」）か、交換する手持ちを選ぶ。どちらかを確定するまで取得・共有の選択は変更せず、閉じればキャンセル。外した回も図鑑に残る。
- 「手持ちエピソード」はスマホ3列×2段、PC6列。手持ち・図鑑のカートリッジから詳細を開き、エピソードへ移動／追加／取り外しができる。図鑑の「手持ち」印は回番号と同じ行に表示する。
- PCはドラッグ、スマホは350msの長押し後のドラッグで、手持ち同士の位置を交換する。通常のタップは詳細、長押し前のスワイプはスクロール。枠外ドロップ・Escape・スクロール・別タブ更新はドラッグを中止する。手持ち欄の「並び替え」では交換したい2本を順に選べ、キーボードでも利用できる。図鑑の詳細には位置変更を置かない。並び順は既存の番号配列に保存する。
- 成功時は枚数と枠の短い強調で示す。読み上げ用通知は残し、保存エラーは画面にも表示する。
- 既存の図鑑記録は維持し、初回のケースは空。今回の選択と手持ちは独立しており、追加せずに次の3択へ進める。
- 未発見枠は共通の軽いシルエットと回番号のみ。画像・タイトル・ケース色は伏せ、未発見の画像は取得しない。
- 「エピソード図鑑」は「新しい順」（番号降順）を初期値とし、「古い順」も選べる。「未発見も表示」は初期オン。並び順と表示設定を端末に保存する。タイトルは3行分の高さを確保して省略し、カートリッジの上端をそろえる。全文は詳細で表示する。
- 手持ちは `takitsubo:episode-lab:party:v1`（番号配列）、図鑑設定は `takitsubo:episode-lab:dex:v1`（order / showUnseen）。存在しない番号・重複・7本目以降を読み込み時に除外する。
- 別タブの図鑑・ケース変更を反映。保存できない場合は画面内だけで保持する。外部サービスの聴取状態や日数制限には依存しない。
- 図鑑の見出し直下に「※このブラウザに保存されます」を表示する。保存できない場合は同じ場所にエラー案内を出す。バックアップ機能は現段階では追加しない。

現在の保存キーは `takitsubo:episode-lab:collection:v1`。値はエピソード番号の配列。
新キーがまだなく旧キー `takitsubo:excavation:v1` に記録がある場合だけ、現在存在する整数のエピソード番号を重複なしで取り込む。
旧記録は削除しない。新キーに移行後は旧記録を参照しない。旧ゲームのコード・ページ・データ形式には依存しない。
保存を使えない場合も、画面内の記録と選択は続けられる。

## 共有

- URL形式: `lab.html?eps=128%2C98%2C16&pick=98`。`eps` は順序を含む3件、`pick` は確定した回（省略可能）。
- 受信者には同じ順序と「紹介した人の選択」を表示。受信者の初期状態は未選択で、受信だけで図鑑に登録しない。
- 不正・重複・存在しない候補は通知して新しい3択へ。不正な `pick` だけなら候補を維持し、選択印だけ省略する。
- 共有画像は1200×800 PNG。実物と同じSVGの3本のカートリッジ・回番号・タイトル（長文は禁則処理付きで省略）・選択印を含む。青い配色で画面と統一。未選択でも保存できる。
- 研究所では「この3択のシェア画像を作る」を押すと画像を表示し、その下に保存・画像コピー・Xの操作を出す。専用のリンクコピーボタンは置かない。取得を確定すると自分の選択を含む画像に更新する。別の人がリンクを開いた場合とは履歴情報で区別する。「別の3択」で画像と操作を閉じ、生成前の状態へ戻す。
- 手持ちシェアは別枠。1200×1100 PNGに手持ちを保存順の3列×2段で配置し、1〜6本に対応する。生成後に保存・コピー・Xの操作を表示し、追加・取り外し・位置交換・別タブでの変更で画像を更新する。空なら共有欄を隠して画像を破棄する。手持ちを受信者へ複製するURLは作らない。
- 診断は結果画像を自動生成して常時表示。ボタンは旧診断のピル型・中央配置と黒いXボタンを両ページで使う。画像生成中の次ラウンド移動・離脱では古い生成結果を表示しない。
- Xへの投稿はユーザー自身が投稿画面で行う。画像は保存後に手動で添付する。
- 共有URLはローカルでも正規の `https://game-takitsubo.com/lab.html` を使う。生成時に `data/site.json` の `base_url` から指定し、3択では候補と選択のクエリを付け、手持ちでは入口URLを使う。ローカルの履歴URLは別に保ち、正規URLへの遷移や公開は行わない。試作中のリンクについての注釈は表示しない。公開・pushは別途承認が必要。
- 画像上部は「ゲームの滝壺｜エピソード研究所」と、3択なら「この3本、どれを聴く？」、手持ちなら「わたしの手持ちエピソード」。画像下部に短いページURLと `#ゲームの滝壺 #滝壺エピソード研究所` を表示する。
- 投稿文はタイトル一覧を繰り返さず、選択や手持ち本数、正規URL、両ハッシュタグを含める。図鑑だけに登録した回や手持ちから外した回は「手持ちに」と表現しない。共有欄の案内文は診断と同じ「画像を保存/コピーしてから、Xのポストに添付すると盛り上がります！」で統一する。
- 静的ページなので、URLごとに3枚を含むOGP画像を自動生成する仕組みではない。

## 実装と検証

「手持ちに加える」の色は `assets/css/lab.css` 冒頭の `--lab-confirm-*` で調整する。
背景・ホバー背景・文字・縁・下側の影・上側のハイライトをまとめて指定できる。
共有PNGは診断と同じ `assets/img/mainlogo.webp` を使い、青いグラデーション、光の帯、泡、コーラルの下線で番組の見た目をそろえる。カートリッジはゲーム画面と同じSVGを再利用する。

共通ヘッダーは診断の次に、PC「研究所」／スマホ「エピソード研究所」を表示する。フッターは「エピソード研究所」。研究所を開いているときはヘッダーのリンクを選択表示する。
トップの泡は、幅1050px超で研究所を上・DBを左・診断を右・AWQを下にした横長のひし形、821〜1050pxで2列、820px以下で横長の泡を縦に並べる。色と配置は機能別クラスで指定し、並び順に依存させない。研究所のアイコンは `hyuuma.webp` を右向きに反転して使う。

`assets/js/lab-loader.js` が研究所でのみ `assets/js/lab/game.js` と `assets/css/lab.css` を読み込む。
共通ヘッダー・フッター・ページ見出し（EPISODE LAB / エピソード研究所）を表示し、独自のEXITは置かない。「動き ON／OFF」はゲーム枠内に置く。ゲーム画面、今回の3択の共有欄、手持ちエピソードの順で並ぶ。離脱時にCSS・監視処理・画像生成処理・オブジェクトURLを終了・解放する。既存の音声プレイヤーは維持する。
背景は静止SVG、動きはCSS中心。WebGL・追加ライブラリ・連続JavaScript描画は使わない。
「動き OFF」、OSの動きを減らす設定に対応。画面外・非表示タブ・モーダル表示中は研究所の浮遊を休止する。
図鑑はモーダルで、Escape／閉じるボタンで戻れる。共有は画面直下で生成・表示し、診断と共通の `assets/js/share-tools.js` で保存・コピー・Xの操作と日本語の禁則処理をそろえる。表示方法は診断の常時表示（既定）と、研究所の `previewMode: 'on-demand'` を分ける。
スマホでも3枚は横並び。狭い画面や長いタイトルでは縦スクロールを許容する。

```text
python scripts/build.py --page lab
# 診断も生成する場合: python scripts/build.py --page lab --page shindan
# データ更新・共通JS/CSS変更時のみ: python scripts/build.py
start-episode-lab.bat
node scripts/test_episode_lab.cjs
node scripts/test_lab_room.cjs
node scripts/test_lab_cartridges.cjs
node scripts/test_lab_selection.cjs
node scripts/test_lab_party.cjs
node scripts/test_lab_simplified.cjs
node scripts/test_lab_collect.cjs
node scripts/test_lab_polish.cjs
node scripts/test_lab_site_frame.cjs
```

PlaywrightとChromeが必要。`NODE_PATH` は既存のインストール先へ指定できる。
テストはGA通信を遮断し、画面・PNG・レポートを `.local-preview/` に出力する。
Windowsの制限環境ではChromeのファイル保存がキャンセルされる場合があるため、PNG実保存は通常のWindows環境でも検証する。
実機のiOS/AndroidのGPU負荷・電池消費は未測定。

旧発掘ゲームのページ・JS・CSS・テスト・起動バッチ・説明書は削除済み。生成処理、トップページ、全ページのフッター、サイトマップからの導線も除去した。

## 生成差分を小さく保つ

研究所のJS/CSSと共有モジュールはページ側の `data-*` にバージョン付きURLを持つ。
研究所専用の変更はサイト共通の互換性バージョンに含めず、`--page lab` で `lab.html` だけを再生成する。
共有モジュール変更時は `--page lab --page shindan`。共通のJS/CSS変更は全体ビルドが必要。
今回はバージョン構成の移行と共通読込の診断JS変更のため全ページを一度更新した。それ以後の研究所の機能・見た目の更新では全ページ再生成は不要。
共通メニューへの研究所追加・トップの泡の配置変更では全体を再生成する。本文やエピソードデータを変更せず、共通ヘッダー・CSSの参照バージョンの更新として、研究所単独の変更とは別コミットにまとめる。
生成HTMLを直接編集しない。公開時に生成する運用への変更は行っていない。
