# エピソード研究所 プロトタイプ

博士が提示する3択から1回を選び、同じ3択を共有する試作。砂浜の発掘版はそのまま残す。

## 起動

Worktree直下の `start-episode-lab.bat` をダブルクリック。
専用サーバー `http://127.0.0.1:8766/lab.html` を開く。
既存の発掘バッチと同じサーバーを再利用するため、両方の図鑑も共有される。
このバッチは公開・ビルド・RSS更新・Git操作をしない。

## 遊び

- `data/search.json` を再利用。第0回を除くエピソードから重複なしの3件を選ぶ。
- 全アートワーク・タイトルを最初から表示する。博士の文字送り、待ち時間、個数制限はない。
- 1組につき1件を選択し、アートワーク図鑑に登録。既に持っている回も選べる。
- 図鑑は発掘版と同じ `takitsubo:excavation:v1` の回番号配列。聴取状態は記録しない。
- 「別の3択に出会う」で即座に再抽選。候補が十分ある場合は直前の3件を除外する。未発見優遇はせず、候補内で等確率。
- エピソードへの移動や選択で再生を自動開始・切り替えしない。

## 共有

- URL形式: `lab.html?eps=128%2C98%2C16&pick=98`。`eps` は順序を含む3件、`pick` は選択した回（省略可能）。
- 受信者には同じ順序と「紹介した人の選択」を表示する。受信だけで図鑑に登録せず、受信者自身が選んだ時に登録する。
- 不正・重複・存在しない候補は通知して新しい3択へ復帰する。不正な `pick` だけなら候補を維持し、選択印だけを省略する。
- 履歴のページ管理情報を維持しながらURLを更新する。ブラウザの戻る・進むは既存のナビゲーションを利用する。
- シェア画像は1200×800 PNG。3枚・回番号・タイトル（長文は省略）・選択印・独自の博士イラストを含む。未選択の状態でも保存可能。
- 画像作成後に保存ボタンを押す。Xへの投稿はユーザー自身が投稿画面で行う。画像は保存後に手動で添付する。
- ローカルではこのPC内でしかリンクを開けない。その旨を画面に表示し、X投稿文にローカルURLを含めない。公開時は現在のサイトURLをリンクに含める。公開・pushは別途承認が必要。
- 固定の静的ページなので、URLごとに3枚を含むOGP画像が自動生成される仕組みではない。3択を画像で紹介するときはPNG保存を使う。

## 実装と検証

`assets/js/lab/game.js` と `assets/css/lab.css` はページ表示時だけ既存のローダーから読み込む。
専用CSS、画像生成処理、オブジェクトURLはページ離脱時に終了・解放する。
画像取得失敗時もカードを選べ、共有画像は回番号とタイトルで生成できる。
保存不可・クリップボード拒否の場合も画面内の図鑑と手動コピーで利用できる。

```text
python scripts/build.py
start-episode-lab.bat
node scripts/test_episode_lab.cjs
```

PlaywrightとChromeが必要。`NODE_PATH` は既存のインストール先へ指定できる。
テストはGA通信を遮断し、画面・PNG・レポートを `.local-preview/` に出力する。
Windowsの制限環境ではChromeのファイル保存がキャンセルされる場合があるため、実ファイル保存は通常Windows環境でも検証する。
