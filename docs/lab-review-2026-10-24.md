# 研究所ブランチの整理・回帰確認

対象: `codex/takitsubo-excavation`。比較元main: `6471908e9dcf970df93bf6f765aab92c02bc7301`。
実行環境: Windows / Chrome 156 / Playwright。公開・mainへのマージ・pushは実施していない。

## 見つかった問題と修正

| 問題 | 再現・影響 | 対応 |
| --- | --- | --- |
| 診断の保存・コピー計測が欠落 | 結果を保存・コピーしても `shindan_save` / `shindan_copy` が発火しない | 共有UIの `onAction` 経由で復元。外部送信を止めたテストで各操作1回ずつの発火を確認 |
| 再診断時に古い画像URLが残る | 「なまえを変えてもう一度」を2回行うと未解放のBlob URLが2個残る | `dispose()` で画像と処理を破棄。再診断後0個、生成中の再診断でも旧結果が復活しないことを確認 |
| 診断の共有モジュール取得失敗が未処理 | 通信を遮断すると「読み込み中…」のままになりJavaScriptエラー | データ取得失敗と同様にメッセージを表示。通常のページ移動は引き続き使える |
| 古い仕様・読み込み方式を前提としたテスト | 旧主ボタンの中央位置、JS総リクエスト数、曖昧な「エピソード」文字列で誤判定 | 現在の主操作、共通スクリプトの重複読込、対象リンクを検証するよう修正 |
| アニメーション検証が描画待ちに依存 | 負荷によって100ms後も最初のフレームが更新されず失敗 | 実際のCSS transitionを中間時点へ進め、初期値・中間値・最終値を比較 |

## ソース整理

- 研究所本体からカートリッジ、保存、ドラッグ、共有PNG、静的HTMLを分離。本体は653行から406行になった。
- `storage.js` に保存キーと互換読み込みを集約。図鑑・手持ち・並び順・色割り当ての形式は維持。
- `lab_version()` で子モジュールを含む全研究所JSを同じ内容由来のバージョンにする。子ファイル変更時のキャッシュ取り残しを防ぎ、研究所だけの変更で他ページを再生成する必要はない。
- CSSは現在使われないリンク用指定、常に上書きされる古い博士表示の指定、未使用変数を除去。ユーザー調整済みのトップの泡の位置は変更していない。
- 保存・コピーUIは診断と研究所で共用するが、結果を常時表示する診断と、手動生成する研究所の違いは維持。
- 新しい依存ライブラリ、フレームワーク、登録回数制限は追加していない。

編集場所は [episode-lab.md](episode-lab.md) の「ソースの案内」を参照。

## 今回変更せず残した改善候補・確認範囲

1. **サイトマップの静的ページ更新日**: `build_sitemap()` は聴き方・おたより・プライバシーの `lastmod` にビルド当日を使う。そのため本文が同じでも別日にビルドすると更新日と差分が変わる。研究所追加以前からの挙動で、日付管理の方針を別途決めてから直す。
2. **全サイトの生成テンプレート**: `scripts/build.py` は2000行を超え、各ページのHTMLを直接持つ。将来的にはページ別のテンプレート分割が候補。ただし毎週更新とマージへの影響が大きいため、今回の研究所整理には含めない。
3. **実機ブラウザと本番キャッシュ**: iOS Safari / Android実機でのクリップボード・長押し・GPU負荷・電池消費、および公開サーバーのCache-Controlはこの検証に含めない。PC Chromeのモバイルエミュレーションと同一視しない。ローカルプレビューは意図的に `no-store` であり、本番通信量の測定には使わない。

今回の検証範囲で、上記修正後に残る再現可能な操作不具合は確認していない。全ページの全機能を網羅した保証ではない。
