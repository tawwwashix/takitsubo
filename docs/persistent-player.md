# 常駐プレイヤーと静的ページ遷移

## 構造と保守

既存のPythonビルドとGitHub Pagesを維持している。各URLに静的HTMLが存在し、直接アクセス、
再読み込み、JavaScriptを無効にした通常リンクの移動は従来どおり使える。

`scripts/build.py` の共通生成処理で、ヘッダー・ヒーロー・本文・フッターを `#sitePage` にまとめる。
ヒーローや見出しが `main` の外にあるため、この枠をページ単位で交換する。
`assets/js/navigation.js` が同一オリジンのHTML/ディレクトリへの通常クリックを取得し、
fetch、HTML解析、枠の交換、タイトル・メタデータ・body属性の更新、履歴・スクロール管理を行う。
外部リンク、修飾キー、中クリック、target、download、メール・電話、処理済みイベントは対象外。
個別に除外するリンクや親要素には `data-no-navigation` を付ける。

`player.js` は文書ごとに一つだけ `audio#tkAudio` と `.tk-mini` をbody直下へ作る。
ページ初期化では再生UIを接続するだけで、audioの作り直し、srcの再設定、pause、load、
再生位置の復元を行わない。別の回の再生操作をしたときだけsrcを切り替える。
同じ回へ戻れば進行中の時刻をページ内UIにも反映する。

ミニプレイヤー右端の`⌄`ボタンはUIだけを48px程度のバーへ縮める。バーには再生/一時停止、
短縮表示されたエピソード名、時刻、`⌃`の展開ボタンを残す。状態は`player.js`のメモリ上の
クラスで保持するため、サイト内遷移・戻る・進むでは維持し、ブラウザ再起動後には引き継がない。
最小化・展開の処理はaudioのイベント、src、currentTime、pause、load、保存位置に触れない。

既存の `tkpos:<回番号>`、`tkrate`、チャプター、位置リンク、Media Sessionを維持。
通常の再読み込み後は保存位置から再開できるが、自動再生はしない。
直接開いた `?t=秒` / `#t=秒` は従来どおり頭出し再生を試みる。
内部遷移で時刻付きの別の回を開いた場合は、現在の音声を継続し、再生ボタンを押して頭出しする。

## ページ固有JavaScript

全ページで同じ6本の小さなスクリプトを1回だけ読み込む。追加依存パッケージはない。
実行可能なscriptを取得先HTMLから再挿入する方式は採らない。

初期化処理は `Takitsubo.register(function (page) { ... })` に登録する。
初回DOMContentLoadedと本文交換時に呼ばれ、該当UIのないページでは何もしない。
各処理は次のように管理する。

- ページ内要素のリスナーは交換されるDOMと一緒に破棄。
- document/windowのリスナーは `page.listen` で登録し、離脱時に解除。
- fetchに `page.signal` を渡し、離脱後の応答は反映しない。
- タイマー、IntersectionObserver、ライトボックスなどは `page.onDispose` で終了。
- 検索とDBがURLを更新するときは `history.state` とハッシュを保持。
- AWQのランキング・答え表示は既存のHTML標準 `details` / `summary` を維持。

CSS・JSの内容ハッシュを生成HTMLに記録し、デプロイ前後のリソースが混ざる場合は通常遷移へ戻す。
新しい共通スクリプトはbuild.pyの `ASSETS` に追加する。

## 失敗時と適用範囲

連続遷移では古いリクエストをキャンセルし、最後の要求だけを反映する。
通信失敗、15秒のタイムアウト、HTML不正、バージョン不一致では通常ページ読み込みにフォールバックする。
その場合や、リロード、別サイトへの同一タブ移動では文書が破棄されるので再生は停止する。
ネットワークやOSによる音声配信そのものの中断までは防げない。

Safari/Firefoxは実機未検証。非対応のIntersectionObserverやMedia Sessionは機能検出で回避する。
fetch、AbortController、History API、DOMParserは現行ブラウザ向け。ブラウザの自動再生制限は従来どおり適用される。

## アクセス解析

既存GA4の拡張計測による履歴変更のページビューを利用し、手動送信を重ねない。
これは [GoogleのSPA計測ガイド](https://developers.google.com/analytics/devguides/collection/ga4/single-page-applications) に沿う。
初回・内部遷移・戻るでページビューが各1回生成され、ページ名と参照元が更新されることを実際のタグで確認した。
テストではgoogle-analytics.com宛てのリクエストを捕捉・遮断し、本番集計へ送っていない。
GAの管理画面で履歴変更の拡張計測を無効にした場合は、この前提を見直す必要がある。

## ブラウザ検証（2026-09-10）

Windows上のChrome 152.0.7977.83（Playwright、headless）を使用。
第122回の実配信MP3を10秒以上再生してから以下のページへ通常リンクで移動した。

エピソード一覧 → 滝壺DB → 名物企画一覧 → わるい村 → ホーム → 戻る2回 → 進む →
AWQ → ゲーム診断 → お知らせ → 聴き方 → おたより → 第121回。

再生位置が10秒台から15秒台まで進み、全地点で同一audio要素・再生状態・音量を確認。
遷移前から `pause`、`emptied`、`loadstart`、`waiting`、`stalled`、`error`、`seeking` を監視し、
遷移中の発生は0件。スクリプトのロード数も6本のままで重複ロードなし。
これは実音源を使ったブラウザの再生状態検証であり、スピーカー出力を人が聴いた聴感試験ではない。

実際に操作した項目:

- エピソード検索、タグ、並び替え、繰り返し移動後の `/` キー。
- DBのひらがな検索とメイン回絞り込み、五十音ハッシュ移動。
- AWQランキングと答えの展開、診断の実行・名前変更・再実行。
- 第121回を表示しただけでは第122回の再生を維持し、再生ボタンで初めて切り替え。
- 一時停止、スキップ、速度、音量の保持、別ページのミニプレイヤーから再開。
- 同じ回への再接続、キーボードでのシーク、チャプター再生とハイライト、位置リンクのコピー、保存位置。
- 個別回のアートワーク拡大とEscapeでの終了。
- 戻る・進む、検索条件とスクロール位置の復元。
- 390×844 / 1280×900の表示、スマホメニュー。
- Ctrl+クリックによる別タブ、Spotifyの外部リンク。
- 修飾キー、ダウンロード、メール・電話、明示除外の非横取り。
- 連続遷移、データ読込途中の離脱、fetch失敗時のフルロード。
- 個別URLの直接アクセス・リロード、JS無効時の静的表示とページ移動。

統合テストのJavaScriptエラーは0件。681個の静的HTMLに交換枠とmainが一つずつあること、
JavaScript構文、ビルド、差分の空白検査も確認。データJSON、sitemap、URL構造、GitHub Actionsは変更なし。

## 再検証

`python scripts/build.py` で再生成する。
Playwrightが利用可能なNode環境（必要なら `NODE_PATH` で既存のインストール先を指定）で実行:

```text
node scripts/test_navigation.cjs
```

ローカルサーバーを起動してChromeでテストし、終了時にサーバーとブラウザを閉じる。
レポートとスクリーンショットは既定でOS一時フォルダー内の `takitsubo-navigation-test` に出力。
`TK_TEST_OUTPUT` で出力先を変更できる。実配信MP3へ接続可能な環境が必要。

GA確認は別途ローカルサーバーを起動したうえで実行する:

```text
python -m http.server 8765 --bind 127.0.0.1
node scripts/test_analytics.cjs http://127.0.0.1:8765
```

今後の改善候補はSafari/iOS・Firefoxでの再生とOSメディア操作の確認、履歴上の診断結果や
AWQ展開状態の復元。現在はURLに保存される検索条件とスクロール位置を復元する。
